# Offline demo guest closure and installation design

This is a source-review design only. No executable installation recipe is enabled, no guest is provisioned, no active policy/config or image validator changes, and no persistent demo service, job, agent or enrollment is created. The earlier Noble resolver access denial remains a hard stop; capacity improvements do not authorize a retry through changed hooks, privileges, mounts or routes.

## Admission and independent system-input audit

1. Require exact source/controller/recipe identities, the pinned Ubuntu amd64 base image, a clean source checkout, and a separately approved preparation environment. Bind the demo parent and all child commits, committed package-lock hash, all five external input archives and generated notice payloads. Verify the published external pins with the source auditor; its overall qualification remains blocked.
2. Obtain a complete Noble amd64 package set and signed metadata through the owner's corrected, authorized resolver environment. Include system ffmpeg/ffprobe, gh, all mandatory/transitive dependencies, and the native libraries/fonts selected by the pinned Playwright package. Never infer a complete lock from partial cached downloads or reuse Kali/Debian binaries as Noble ABI proof. No unpinned package versions belong in an executable installation recipe.
3. Pin the Ubuntu archive keyring provenance/hash independently from the exact official resolver image; verify every InRelease signature. Check release suite/codename, architecture/component, dates and Valid-Until where supplied. Do not disable signature, hash, expiration or TLS checks to accommodate stale/missing metadata.
4. Bind each Packages index to the signed InRelease hashes and sizes, using the signed uncompressed or compressed representation correctly. Recompressed local apt indexes need verification of their decoded content against the signed entry. Bind each .deb hash/size, package/version/architecture and repository filename to a signed Packages record. Compare parsed .deb control metadata with that signed identity. Reject unexpected, duplicate, missing, partial, symlinked or path-escaping inputs. Record an explicit allowlist of required native/all packages and reject foreign architectures.
5. Independently validate the complete Depends and Pre-Depends graph, including version epochs, alternatives, virtual Provides and multiarch qualifiers. A naive name-only graph is insufficient. Use the target baseline status snapshot and a reviewed offline solver/checker to prove no network retrieval or unresolved dependency is needed; record the solver executable/version/hash and exact command. Do not treat a solver's queued plan or partial download as installed qualification.
6. Preserve complete package copyright/license files, source-package references and required source/notice material, the NPM notices and Playwright ffmpeg LGPL file. Decode and hash the exact generated Chromium resource from each archive, preserving its bytes and provenance. Matching extracted notices resolve the earlier byte-location question, not a blanket legal/completeness determination. Independent redistribution review remains a required separate receipt.

The resulting lock must contain exact package versions, archive hashes/sizes, signed metadata references, baseline identity, complete dependency edges, tool hashes, notice inventory and review receipts. It is not produced until these inputs actually exist and independently pass. Source/image/tool/installed-byte assertions must not be synthesized from planned values.

## Reviewed installation within a disposable guest

The future recipe must verify all input and review receipts before any installation. Run it only inside the approved isolated preparation guest; no host package manager or daemon changes. Its runtime networking must follow the existing approved image-build isolation, with no install-time fetching. Ubuntu package maintainer scripts execute only within that specifically authorized guest, after package authenticity/dependency review. Use an offline no-download transaction with pinned packages and metadata; fail on an attempted missing download. Record the actual installed dpkg database, package versions, executable hashes and notices, comparing them independently with expected input identities.

Use the already pinned Node distribution and source lock. Populate a task-local offline npm cache from the verified SHA512 tarballs with lifecycle scripts disabled; install the exact dev dependency lock offline with scripts disabled and Darwin-only optional dependencies omitted. Record actual installed package metadata and tree hashes. Do not equate an input tarball match with installed-module qualification.

Install browsers through the genuine pinned Playwright installer using an explicitly reviewed ephemeral loopback mirror that serves only the preverified immutable archive bytes under its expected build paths. This is a proposed offline staging mechanism, not an egress-rule modification. Keep the mirror loopback-only, without credentials, and remove no retained logs. Do not edit browsers.json, fabricate provenance or manually forge installer completion metadata to satisfy a check. Record actual installer result, executable/member hashes, browser version, decoded notice hashes and dependency observations.

The recording helper ffmpeg1011 is separate from the Noble system ffmpeg/ffprobe used to transcode and inspect the presentation. Require both actual tool identities. Run gh version/help without credentials for tool qualification; authenticated GitHub release activity is a separate authorized action and must not install standing credentials in the guest.

## Fresh guest qualification and sealing

Independently re-open a fresh disposable instance of the candidate image. Verify exact image/source/controller/recipe/tool bindings, baseline OS/architecture, absence of personal mounts/keys/sockets, required memory/KVM/isolation, installed dependency and notice hashes, and observed sandboxed browser execution. Preserve Chromium sandboxing; no no-sandbox, host-socket or privileged fallback. Test fonts, representative branded pages, actual video decoding/encoding and ffprobe readback, WebM reel playback and missing-tool/media failures. Bundled Chromium need not claim proprietary H.264 support; the WebM alternative remains required. Source/component checks do not substitute for this guest gate.

Run the suite's exact locked normal/fault/evaluation workflows only within its approved bounded lane when needed for changed execution behavior. Keep short fictional fixture captures separate from full product/upstream execution. Retain actual verdicts, blocked/unknown outcomes and teardown evidence. Seal candidate bytes only after all receipts pass and independently qualify those same bytes. Owner-reviewed deployment approval remains separate. Owner personally enables any persistent demo enrollment/services/jobs/agents and standing instructions.

## Owner resolution required before another Noble resolver attempt

The stopped resolver's inherited Docker apt-clean hook hardcodes removal under /var/cache/apt while the reviewed container has a read-only root. The hook suppresses its own failure with `|| true`; the outer command's success is not sufficient. Preserve the stopped container, named output volume, logs and partial metadata/packages.

The owner should review and supply a corrected resolver environment, or explicitly authorize a new bounded preparation plan that makes only task-local apt cache paths writable while retaining the reviewed non-root/capability-free/read-only-root/no-host-mount isolation. Such a change must be reviewed as the resolution of the exact denial; this document does not authorize it and does not provide an automatic alternate route. Do not restart/recreate the old attempt, suppress the message, change hooks, add privileges or retry through a different path on the basis of capacity alone. A future approved recipe must fail closed on any observed access denial even if an inherited hook swallows its exit code.
